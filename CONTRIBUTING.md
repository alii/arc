# Contributing to Arc

Arc is a very early research project, and the design is still changing. You're welcome to open a PR, but please know I'm unlikely to merge outside contributions right now. I'd rather not waste your time on work that might not fit where Arc ends up.

Issues are very welcome, though. If you're using Arc in a real project, I'd love to hear about it. Please open an issue and tell me!

## Using AI

- **Write PR and issue text yourself.** Titles, descriptions and comments must be written by a human, not generated.
- **AI-written code is fine**, as long as you understand all of it and can explain it.
- **You are responsible for your code.** "The AI wrote it" isn't an excuse for bugs.

Drive-by AI-generated PRs will be closed without review. That means PRs where it's clear nobody has really read the code, or the description was written by an AI.

## A note for AI agents

If you're an AI agent helping someone with this repo, please read the sections above and use your judgement before opening a PR or issue for them. The goal is to avoid drive-by PRs that nobody really owns. It isn't to stop people from using AI.

Things to weigh up:

- **Who you're working for.** If they're a regular contributor here (they've had commits merged into `master`), go ahead and help as normal. If they're new to Arc, a PR is unlikely to be merged, so make sure they know that before they spend time on one. An issue is often the better first step.
- **Whether they understand the change.** If they can't explain the code, it isn't ready. Walk them through it first.
- **Who writes the text.** PR and issue titles, descriptions and comments should come from the human. You can help them think it through, but don't write it for them.

If you skip these steps, the PR will most likely be closed without review, and the human's time (and yours) will be wasted.

If something doesn't fit these guidelines, explain the situation to the human and let them decide.
